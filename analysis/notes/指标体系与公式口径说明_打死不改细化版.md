# 指标体系与公式口径说明：打死不改细化版

## 0. 文档目的

本文档用于统一本研究中 GenAI / LLM 暴露度、城市端 GenAI 需求强度、岗位技能结构、技能熵、技能结构重塑指数、城市分类与模型变量的计算口径。

本文件以已经存在的 `第二条主线全部公式汇总_打死不改最终版.md` 为核心基础，不推翻其中已经固定的核心公式。本文档只补充和细化变量来源、计算层级、聚合规则、缺失处理、输出字段和模型使用方式。

若代码实现与本文档口径冲突，以本文档口径为准；冲突处必须在阶段性结果汇总或后续运行日志中标注。不能为了让模型结果更好看而静默删除样本、替换变量含义或修改核心公式。

需要特别说明：当前“打死不改最终版”的 `GDI_c` 不是外部宏观意义上的 GDP、数字经济指数或综合城市数字基础指数，而是城市招聘文本中显性 GenAI / LLM 岗位占比。若论文正文要继续使用“城市数字基础”表述，必须在后续人工确认：是沿用当前 `GDI_c = 显性 GenAI 需求强度`，还是另行补充外部城市数字基础数据并重新命名。

## 1. 研究层级与基本符号

本研究当前主口径包含四个基本层级。

| 符号 | 含义 | 层级 | 当前字段或来源 |
|---|---|---|---|
| `i` | 招聘岗位记录 | 岗位层 | `job_id` 对应的一行招聘记录 |
| `c` | 城市 | 城市层 | 由 `city_std` 经标准化得到 `city` |
| `g` | 岗位族 | 岗位族层 | 正文主口径为 15 类 `job_family_mapping_v2_15class`；18 类为稳健性；早期用 `keyword_seed` 代理 |
| `s` | 技能标签 / 技能 token | 技能层 | `job_tags_raw` 拆分或 `skill_tokens_v2_1` 抽取得到 |

当前核心分析单元是 `city × job_family`，即城市 `c` 与岗位族 `g` 的组合单元。岗位层用于提取技能、构造 LLM 暴露得分与显性 GenAI 岗位标记；`city × job_family` 层用于构造机制模型主表；城市层用于城市排名、城市分类、地区比较和结论解释；岗位族层用于定义 `Exposure_g`。

| 符号 | 含义 | 层级 |
|---|---|---|
| `n_cg` | 城市 `c` 中岗位族 `g` 的招聘数量 | `city × job_family` |
| `n_c` | 城市 `c` 的招聘总量 | 城市层 |
| `share_cg` | 岗位族 `g` 在城市 `c` 中的招聘占比，`n_cg / n_c` | `city × job_family` |
| `GenAI_i` | 岗位 `i` 是否为显性 GenAI / LLM 岗位 | 岗位层 |
| `llm_exposure_total_i` | 岗位 `i` 的 LLM 综合暴露分 | 岗位层 |
| `Exposure_g` | 岗位族 `g` 的 GenAI / LLM 暴露度 | 岗位族层 |
| `Exposure_c` | 城市 `c` 的结构加权岗位暴露度，建议输出变量 | 城市层 |
| `GDI_c` | 当前打死不改版中的城市 GenAI / LLM 需求强度 | 城市层 |
| `SRI_cg` | 城市 `c` 中岗位族 `g` 的技能结构重塑程度 | `city × job_family` |
| `SRI_c` | 城市 `c` 的整体技能结构重塑程度，建议由 `SRI_cg` 加权聚合 | 城市层 |
| `H_cg` / `SkillEntropy_cg` | 城市 `c` 中岗位族 `g` 的技能熵 | `city × job_family` |
| `H_c` / `entropy_c` | 城市 `c` 的整体技能熵 | 城市层 |

## 2. 原始字段与统一变量口径

字段名以当前代码中实际存在字段为准。若字段在某个输入文件中缺失，不得自行假设，应在“待确认问题”中记录。

| 原始字段 | 统一变量名 | 含义 | 用途 | 备注 |
|---|---|---|---|---|
| `job_id` | `job_id` | 岗位唯一标识 | 去重、追踪、岗位层合并 | 当前 51job 清洗表和 LLM 评分表均使用该字段 |
| `city_std` | `city` / `c` | 标准化前城市字段 | 城市层聚合、城市分类、城市固定效应 | `panel_utils.normalize_city` 按 `-` 或 `·` 截取前段 |
| `keyword_seed` | `keyword_seed` | 抓取关键词或早期岗位族代理 | 早期 `job_family` 代理、LLM 文本拼接 | 不建议作为正文主模型岗位族 |
| `job_title_std` | `job_title` | 标准化岗位标题 | 岗位族映射、LLM 文本拼接 | `job_family_mapping_v1` 由标题优先、关键词辅助 |
| `job_family` | `job_family` / `g` | 岗位族 | 岗位族暴露度、`city × job_family` 聚合 | 正文主口径为 15 类映射；若字段不存在，先用 `keyword_seed` 代理并标记来源 |
| `job_tags_raw` | `skills_raw` | 原始技能标签 | 基础技能提取、技能熵、SRI 的早期输入 | 基础版按竖线分隔符拆分；v2.1 还会扫描 `jd_text_clean` |
| `jd_text_clean` | `jd_text` | 清洗后的职位描述 | v2.1 技能补充、LLM 任务信号匹配 | 只扫描前 `jd-max-chars=1200` 字符用于 v2.1 技能补充 |
| `salary_avg_month` | `salary` | 月均薪资 | 控制变量、描述统计 | 缺失保留，不因薪资缺失删除样本 |
| `salary_avg_annualized` | `salary_annual` | 年化薪资 | 控制变量、描述统计 | 可选 |
| `education_std` | `education` | 学历要求 | 控制变量 | 映射为 `education_score` |
| `experience_std` | `experience` | 经验要求 | 控制变量 | 映射为 `experience_years` |
| `publish_time_std` | `publish_date` | 发布时间 | 时间范围、稳健性、描述统计 | 当前主要用于样本时期检查 |
| `llm_native_signal_score` | `llm_native_signal_score` | LLM 原生应用信号得分 | 构造 `GenAI_i` 与 `GDI_c` | `>0` 视为显性 GenAI / LLM 岗位 |
| `llm_exposure_total` | `llm_exposure_total_i` | 岗位层 LLM 综合暴露分 | 构造 `Exposure_g` | 0-100 分 |

若没有稳定的 `job_family` 字段，统一使用 `keyword_seed` 作为临时代理，并在输出表中保留 `job_family_source = keyword_seed`。当前正文主模型不建议使用该代理口径，而应使用 `job_family_mapping_v2_15class`；18 类 `job_family_mapping_v1_18class` 作为稳健性。

学历分数按 `panel_utils.EDUCATION_SCORE_MAP` 映射：

| 学历 | 分数 |
|---|---:|
| 初中及以下 | 1 |
| 高中 / 高中/中专 / 中专 / 中技/中专 | 2 |
| 大专 | 3 |
| 本科 | 4 |
| 硕士 | 5 |
| 博士 | 6 |

经验年限按 `panel_utils.parse_experience_years` 映射：`无需经验`、`应届`、`在校生/应届生` 记为 0；`x年` 记为 `x`；`x年及以上` 记为 `x`；`x-y年` 记为区间均值。

## 3. 技能清洗与技能集合定义

当前仓库中存在两套技能提取口径，需要在使用时区分。

第一套是基础 `job_tags_raw` 拆分口径，主要由 `src/analysis/panel_utils.py`、`src/analysis/build_panel_cg_base.py` 和 `src/analysis/compute_entropy.py` 使用。它将 `job_tags_raw` 按 `|` 拆分，去除空值、首尾空格、重复标签、学历经验标签和明显福利待遇类标签，得到基础技能 token。

第二套是当前机制模型和 SRI 使用的 v2.1 控制技能 token 口径，主要由 `src/analysis/build_skill_tokens_v2_1.py` 和 `src/analysis/skill_v2_1_utils.py` 生成。它先从 `job_tags_raw` 抽取候选 token，再在需要补充时扫描 `jd_text_clean` 前 1200 字符，最后用 `finalize_skill_tokens_v2_1` 合并强技能 token 与有限 fallback token。当前 SRI 的 `GenAIShare_cg`、`DigitalShare_cg`、`HighOrderShare_cg`、`RoutineShare_cg` 均基于 v2.1 技能 token 及其类别。

对每条招聘记录 `i`，定义清洗后技能集合：

```text
S_i = {s_1, s_2, ..., s_k}
```

通用规则如下：

1. 去除空值。
2. 去除首尾空格并压缩连续空白。
3. 去除首尾异常分隔符，如 `,`、`，`、`;`、`；`。
4. 同一岗位内重复标签去重，大小写归一后同一 token 最多保留一次。
5. 剔除明显非技能类标签。
6. 保留能反映岗位能力要求、工具要求、知识要求、任务要求、技术要求、业务能力的标签。

同一岗位 `i` 中，同一技能 `s` 最多计一次；不同岗位中重复出现的同一技能分别计数。技能频次以“包含该技能的岗位数量”为基础，而不是同一岗位内原始标签重复出现次数。无有效技能标签的岗位仍保留在岗位数量统计中，但不参与技能熵和原始技能结构 share 的计算。

基础版非技能标签剔除原则如下：

| 类别 | 剔除示例 | 当前代码依据 |
|---|---|---|
| 学历类 | 本科、大专、硕士、博士、高中/中专 | `SKILL_STOP_EXACT` |
| 经验类 | 无需经验、应届、在校生/应届生、`x年`、`x-y年` | `looks_like_experience_token` |
| 福利待遇类 | 五险、公积金、年假、餐补、包吃、包住、体检、团建 | `SKILL_STOP_SUBSTRINGS` |
| 薪酬激励类 | 奖金、绩效、津贴、年终奖、提成、底薪 | `SKILL_STOP_SUBSTRINGS` |
| 工作制度类 | 双休、周末、弹性工作、做五休二 | `SKILL_STOP_EXACT` 与 `SKILL_STOP_SUBSTRINGS` |
| 其他非能力要求 | 交通便利、团队氛围、晋升空间、人性化 | `SKILL_STOP_SUBSTRINGS` |

v2.1 口径还包含以下额外规则：

| 规则 | 说明 |
|---|---|
| `DIRECT_DROP_TOKENS_V2_1` | 直接丢弃过泛 token，如 `英语`、`word`、`ppt`、`客户开发` 等 |
| `FALLBACK_ONLY_TOKENS_V2_1` | 仅在没有强技能 token 时限量使用，如 `excel`、`项目管理`、`技术支持` 等 |
| `fallback_cap = 2` | 若没有强技能 token，最多保留 2 个 fallback token |
| `JD_TOPUP_EXEMPT_CATEGORIES_V2_1` | 若标签中已有编程、数据库、AI 数据等强技术类 token，可不再扫描 JD 补充 |
| `token_category_v2_1` | 为每个标准技能 token 标注类别，用于后续 share 和 SRI |

## 4. `city × job_family` 基础统计指标

城市 `c` 中岗位族 `g` 的岗位数量为：

```text
n_cg = count(i: city_i = c, job_family_i = g)
```

城市 `c` 的总岗位数量为：

```text
n_c = sum_g n_cg
```

岗位族 `g` 在城市 `c` 中的招聘结构占比为：

```text
share_cg = n_cg / n_c
```

`share_cg` 表示岗位族 `g` 在城市 `c` 招聘结构中的占比，是后续城市层面加权聚合的核心权重。

基础输出字段建议如下：

| 字段 | 含义 | 当前对应字段 |
|---|---|---|
| `city` | 城市 | 已有 |
| `job_family` | 岗位族 | 已有 |
| `job_family_source` | 岗位族来源 | 已有 |
| `n_cg` | 单元岗位数 | 当前多表中名为 `job_count` |
| `n_c` | 城市岗位总数 | 当前多表中名为 `city_total_jobs` 或 `total_jobs` |
| `share_cg` | 城市内岗位族占比 | 需由 `job_count / city_total_jobs` 派生 |
| `salary_mean` | 单元月薪均值 | 当前名为 `avg_salary_month` |
| `education_mean` | 单元学历分数均值 | 当前名为 `avg_education_score` |
| `experience_mean` | 单元经验年限均值 | 当前名为 `avg_experience_years` |
| `publish_date_min` | 最早发布时间 | 已有 |
| `publish_date_max` | 最晚发布时间 | 已有 |
| `quality_flag` | 单元质量标记 | 当前基础表已有 `quality_flag`，机制表另有 `sample_size_flag` |

主结果底表应保留所有 `n_cg > 0` 的 `city × job_family` 单元，不得在主表中悄悄删除小样本单元。样本过滤只能发生在模型估计或稳健性估计阶段，并必须记录过滤规则。

建议最终统一的样本量质量标记为：

| 条件 | 建议标记 |
|---|---|
| `n_cg >= 30` | `good` |
| `10 <= n_cg < 30` | `medium` |
| `5 <= n_cg < 10` | `low` |
| `n_cg < 5` | `very_low` |

当前机制模型中已存在类似字段 `sample_size_flag`：

| 当前值 | 含义 |
|---|---|
| `ge20_preferred` | `job_count >= 20`，优先用于解释 |
| `10_to_19_usable_with_caution` | `10 <= job_count < 20`，主样本可用但需谨慎 |
| `5_to_9_appendix_only` | `5 <= job_count < 10`，建议仅附录或稳健性 |
| `lt5_not_recommended` | `job_count < 5`，不建议单独解释 |

## 5. 技能频次、技能覆盖率与技能熵

定义 `city × job_family × skill` 的技能频次：

```text
N_cgs = 城市 c、岗位族 g 中包含技能 s 的岗位数量
```

定义该单元全部技能出现次数：

```text
N_cg. = sum_s N_cgs
```

定义技能占比：

```text
p_cgs = N_cgs / N_cg.
```

定义 `city × job_family` 技能熵：

```text
H_cg = - sum_s p_cgs * ln(p_cgs)
```

当前代码中该变量在基础输出中名为 `entropy_cg`，在机制模型中重命名为 `SkillEntropy_cg`。`H_cg` 越高，表示该单元内技能需求越分散、越多元；`H_cg` 越低，表示技能需求越集中。

城市层面技能频次为：

```text
N_cs = 城市 c 中包含技能 s 的岗位数量
p_cs = N_cs / sum_s N_cs
H_c = - sum_s p_cs * ln(p_cs)
```

当前城市层技能熵变量名为 `entropy_c`。

技能类指标应同时输出：

| 字段 | 含义 | 当前对应字段 |
|---|---|---|
| `skill_job_count` | 至少包含一个有效技能的岗位数量 | 已有 |
| `skill_coverage_ratio` | `skill_job_count / n_cg` | 已有 |
| `unique_skill_count` | 单元内不同技能数量 | 已有 |
| `skill_token_count` / `total_skill_count` | `sum_s N_cgs` | 基础表为 `skill_token_count`，机制表为 `total_skill_count` |
| `H_cg` / `SkillEntropy_cg` | 单元技能熵 | 已有 |
| `skill_valid` | 是否可以计算技能类指标 | 建议新增，由 `total_skill_count > 0` 判断 |

缺失规则：

1. 若某个 `city × job_family` 单元没有有效技能，则 `H_cg` 应为空，不用 0 代替不可计算值。
2. 当前 `compute_entropy.py` 对空技能计数表会输出空表；无技能单元在与 entropy 表合并后自然为缺失。
3. 城市层聚合时，只在有效技能样本范围内计算技能熵，并同时报告覆盖率。
4. `SRI_cg_smooth` 因引入岗位族 prior 平滑，可能在无技能 token 单元中仍给出数值；解释时必须同时查看 `skill_coverage_ratio_cg` 和 `sample_size_flag`。

## 6. GenAI / LLM 暴露度指标

当前打死不改版使用 7 维轻量规则型 LLM exposure proxy。岗位层文本先拼接为：

```text
Text_i = lower(keyword_seed_i + job_title_std_i + job_tags_raw_i + skill_tokens_v2_1_i + jd_text_clean_i)
```

实际代码会跳过空字段，用 ` | ` 连接，替换全角空格并压缩连续空白。`city_std` 不参与文本匹配。

7 个维度如下：

| 短符号 | 变量名 | 中文含义 | 是否正向 | 主要来源字段 | 计算方式 |
|---|---|---|---|---|---|
| `ln` | `llm_native_signal` | LLM 原生应用信号 | 暴露正向、替代正向、增强正向 | `keyword_seed`、`job_title_std`、`job_tags_raw`、`skill_tokens_v2_1`、`jd_text_clean` | 命中“大模型、LLM、AIGC、RAG、智能体、模型训练”等信号组 |
| `tk` | `text_knowledge_work` | 文本生成与知识处理 | 暴露正向、替代强正向、增强轻度正向 | `job_title_std`、`job_tags_raw`、`skill_tokens_v2_1`、`jd_text_clean` | 命中写作、编辑、翻译、答疑、资料整理、研究报告等信号组 |
| `dc` | `data_code_assistance` | 数据分析与编程辅助 | 暴露正向、增强强正向 | `job_title_std`、`job_tags_raw`、`skill_tokens_v2_1`、`jd_text_clean` | 命中 Python、Java、SQL、数据分析、BI、API、Git、Docker 等信号组 |
| `sr` | `structured_routine_work` | 结构化流程与规则任务 | 暴露正向、替代强正向、增强负向 | `job_title_std`、`job_tags_raw`、`skill_tokens_v2_1`、`jd_text_clean` | 命中 Excel、ERP、OA、录入、对账、开票、订单、报表、SOP 等信号组 |
| `rt` | `relationship_trust_work` | 人际沟通与信任协商 | 替代负向、增强正向 | `keyword_seed`、`job_title_std`、`skill_tokens_v2_1`、`jd_text_clean` | 命中客户维护、客户沟通、商务谈判、咨询、培训、宣讲等信号组 |
| `hj` | `high_judgment_work` | 高判断与复杂决策互补 | 替代负向、增强正向 | `keyword_seed`、`job_title_std`、`skill_tokens_v2_1`、`jd_text_clean` | 命中方案设计、策略、需求分析、项目管理、风控、审计、评估等信号组 |
| `po` | `physical_offline_work` | 线下实体执行抗替代 | 替代强负向、增强负向 | `keyword_seed`、`job_title_std`、`skill_tokens_v2_1`、`jd_text_clean` | 命中现场、安装、维修、施工、仓储、导购、配送、护理、保安、餐饮等信号组 |

每个维度有 3 个信号组。某个信号组内只要任一关键词命中，该信号组计 1 次命中。设 `M_id` 为岗位 `i` 在维度 `d` 上命中的信号组数量：

```text
Score_id = clamp01(M_id / 2.5)
clamp01(x) = min(max(x, 0), 1)
```

输出文件中各维度保存为 0-100 分，例如：

```text
llm_native_signal_score = 100 * ln
```

岗位层核心得分公式如下：

```text
I = clamp01(0.34*ln + 0.24*tk + 0.22*dc + 0.20*sr)
llm_exposure_intensity = 100*I
```

```text
R = clamp01(0.30*tk + 0.28*sr + 0.18*ln + 0.08*I - 0.18*rt - 0.16*hj - 0.18*po - 0.04*dc)
llm_substitution_risk = 100*R
```

```text
A = clamp01(0.30*dc + 0.22*hj + 0.18*rt + 0.16*ln + 0.10*tk - 0.10*sr - 0.10*po)
llm_augmentation_potential = 100*A
```

综合暴露分为：

```text
T = clamp01(0.45*I + 0.30*R + 0.25*A)
llm_exposure_total = 100*T
```

岗位层显性 GenAI / LLM 标记为：

```text
GenAI_i = 1 if llm_native_signal_score_i > 0 else 0
```

岗位族层 GenAI / LLM 暴露度为：

```text
Exposure_g = mean(llm_exposure_total_i | i in g)
```

当前主模型使用岗位族映射后的 15 类岗位大类计算 `Exposure_g`；18 类作为稳健性；不得用原始 `keyword_seed` 悄悄替换正文主口径。

城市整体结构暴露度建议输出为：

```text
Exposure_c = sum_g share_cg * Exposure_g
```

它表示城市招聘结构对高 LLM 暴露岗位族的加权暴露。当前仓库中已存在的 `llm_exposure_total_city` 是城市内岗位层 `llm_exposure_total_i` 的均值，不完全等同于 `Exposure_c`，二者应分列。

城市 × 岗位族暴露贡献建议输出为：

```text
X_cg = share_cg * Exposure_g
```

注意：当前机制模型中已有 `GDI_x_Exposure = GDI_c * Exposure_g`，它是交互项，不是城市结构加权贡献 `share_cg * Exposure_g`。

标准化规则：

```text
Exposure_g_z = (Exposure_g - mean(Exposure_g)) / sd(Exposure_g)
Exposure_c_z = (Exposure_c - mean(Exposure_c)) / sd(Exposure_c)
```

当前代码中的 `zscore` 使用总体标准差口径 `ddof=0`。如果后续脚本改用样本标准差，需在结果汇总中标注。

## 7. 城市端变量 `GDI_c`

当前打死不改版中，`GDI_c` 的定义是城市 GenAI / LLM 需求显性化程度：

```text
GDI_c = sum_{i in c} GenAI_i / N_c
GenAI_i = 1(llm_native_signal_score_i > 0)
```

其中 `N_c` 是城市 `c` 的岗位总数。该变量衡量招聘市场中直接写出 GenAI / LLM 原生需求的岗位占比。它不是外部宏观数字经济水平，也不是综合城市数字基础指数。

如果论文最终确实需要“城市数字基础水平”意义上的 `GDI_c`，应另行补充城市层原始数据，并建议改名为 `DigitalFoundation_c` 或 `DigitalBase_c`，避免与当前模型已使用的 `GDI_c` 混用。通用合成公式可写为：

```text
DigitalFoundation_c = sum_k w_k * z_ck
```

正向指标 Min-Max 标准化：

```text
z_ck = (x_ck - min(x_k)) / (max(x_k) - min(x_k))
```

负向指标 Min-Max 标准化：

```text
z_ck = (max(x_k) - x_ck) / (max(x_k) - min(x_k))
```

若使用等权重：

```text
w_k = 1 / K
```

但截至本次检查，当前仓库已跑通的主模型没有使用外部综合数字基础指数。此处只能作为待替换通用口径，不能直接写成当前实证已采用公式。

模型使用时当前已输出：

```text
GDI_c
GDI_c_z
```

其中 `GDI_c_z` 是城市层 `GDI_c` 的 z-score。

## 8. 技能结构重塑指数 `SRI`

`SRI_cg` 表示城市 `c` 中岗位族 `g` 在 GenAI / LLM 冲击下技能需求结构发生调整或重塑的程度。当前正文主因变量为：

```text
SRI_cg_smooth
```

它由四类技能 share 经岗位族 prior 平滑和 z-score 标准化后合成。

### 8.1 四类技能 share

四类 share 来自 `city × job_family × skill_token` 的 v2.1 技能 token 计数，不是手工填值。

| 变量 | 含义 | 计数来源 |
|---|---|---|
| `GenAIShare_cg` | GenAI / AI 算法类技能 token 占比 | `skill_group_ai_view = ai_algorithm` |
| `DigitalShare_cg` | 数字化技能 token 占比 | `AI_BROAD_GROUPS`，包括 AI 算法、数据编程、数字平台自动化、智能制造工业数字化、数字内容平台运营 |
| `HighOrderShare_cg` | 高阶技能 token 占比 | `HIGH_ORDER_CATEGORIES` 或 GenAI 技能 |
| `RoutineShare_cg` | routine 技能 token 占比 | 企业系统、自动化平台、财务供应链、人事行政、零售物流、销售服务、语言办公等 routine 类别 |

一般 share 形式为：

```text
Share_raw_cg,v = C_cg,v / D_cg
```

其中 `C_cg,v` 是单元 `cg` 中第 `v` 类技能 token 计数，`D_cg` 是该单元的 `total_skill_count`。

### 8.2 share 平滑

当前主模型使用 `lambda = 10` 的平滑 share：

```text
Share_smooth_cg,v = (C_cg,v + lambda * prior_g,v) / (D_cg + lambda)
```

参数解释：

| 参数 | 含义 |
|---|---|
| `C_cg,v` | `city × job_family` 单元中第 `v` 类技能 token 的计数 |
| `D_cg` | 该单元 `total_skill_count` |
| `prior_g,v` | 岗位族 `g` 在全样本中的第 `v` 类平均 share |
| `lambda` | 平滑强度，正文主口径固定为 10 |

脚本同时比较 `lambda = 5 / 10 / 20`，但正文主口径使用 `lambda = 10`。平滑是为了降低小样本、小分母单元中 share 接近 0 或 1 的离散波动，不是为了制造结果。未平滑版本 `SRI_cg_raw` 用于稳健性。

### 8.3 SRI 合成公式

所有 Z-score 均在主建模样本内计算：15 类岗位大类，`job_count >= 10`。

```text
Z(V) = (V - mean(V in main modeling sample)) / sd(V in main modeling sample)
```

设 `G_cg`、`D_cg`、`H_cg`、`Q_cg` 分别表示平滑后的 `GenAIShare_cg`、`DigitalShare_cg`、`HighOrderShare_cg`、`RoutineShare_cg`，则正文主因变量为：

```text
SRI_cg_smooth
= Z(GenAIShare_cg_smooth)
+ Z(DigitalShare_cg_smooth)
+ Z(HighOrderShare_cg_smooth)
- Z(RoutineShare_cg_smooth)
```

解释：

| 分项 | 方向 | 含义 |
|---|---|---|
| `GenAIShare_cg_smooth` | 正向 | GenAI 技能越高，说明越 GenAI 化 |
| `DigitalShare_cg_smooth` | 正向 | 数字化技能越高，说明越数字化 |
| `HighOrderShare_cg_smooth` | 正向 | 高阶技能越高，说明越高阶化 |
| `RoutineShare_cg_smooth` | 负向 | routine 技能越高，说明越偏流程化和常规化 |

未平滑版本为：

```text
SRI_cg_raw
= Z(GenAIShare_cg_raw)
+ Z(DigitalShare_cg_raw)
+ Z(HighOrderShare_cg_raw)
- Z(RoutineShare_cg_raw)
```

缩尾稳健性版本为：

```text
SRI_cg_smooth_winsor = min(max(SRI_cg_smooth, q_0.01), q_0.99)
```

其中 `q_0.01` 和 `q_0.99` 是主样本中 `SRI_cg_smooth` 的 1% 和 99% 分位数。

城市层面聚合建议为：

```text
SRI_c = sum_g share_cg * SRI_cg
```

如果某些 `city × job_family` 单元无法计算 `SRI_cg`，则城市层聚合时使用有效岗位族重新归一化权重：

```text
share'_cg = share_cg / sum_{g in G_valid} share_cg
SRI_c = sum_{g in G_valid} share'_cg * SRI_cg
```

截至本次检查，当前仓库已生成 `SRI_cg_smooth`，但尚未发现按上述权重聚合后的正式 `SRI_c` 城市层输出表。

## 9. 交互项与模型变量

模型主表基于 `city × job_family` 层级。

当前主模型为：

```text
Y_cg = beta1 * GDI_x_Exposure_z + city FE + job_family FE + error
```

其中：

| 变量 | 含义 |
|---|---|
| `Y_cg` | `city × job_family` 层面的结果变量 |
| `GDI_c` | 城市 GenAI / LLM 需求强度 |
| `Exposure_g` | 岗位族 LLM 暴露度 |
| `GDI_x_Exposure` | 原始交互项，`GDI_c * Exposure_g` |
| `GDI_x_Exposure_z` | 当前 v3 模型核心解释变量 |
| `city FE` | 城市固定效应 |
| `job_family FE` | 岗位族固定效应 |

可选结果变量包括：

| 变量 | 模型角色 |
|---|---|
| `SRI_cg_smooth` | 核心因变量 |
| `GenAIShare_cg_smooth` | 直接机制变量 / 辅助因变量 |
| `SkillEntropy_cg` | 技能复杂度 / 补充因变量 |
| `SRI_cg_raw` | 未平滑稳健性因变量 |
| `SRI_cg_smooth_winsor` | 缩尾稳健性因变量 |

在包含城市固定效应和岗位族固定效应的模型中，`GDI_c` 与 `Exposure_g` 的单独效应会分别被城市固定效应和岗位族固定效应吸收，因此重点解释交互项。

必须特别注意：

```text
当前 v3 模型中的 GDI_x_Exposure_z
= Z(GDI_c * Exposure_g)
```

它不是：

```text
GDI_c_z * Exposure_g_z
```

早期底表中曾存在 `GDI_x_Exposure_z = GDI_c_z * Exposure_g_z` 的中间变量；当前 v3 脚本会把该旧变量保留为 `GDI_x_Exposure_z_input`，并重新对原始乘积 `GDI_x_Exposure` 在估计样本内标准化。

当前三组主模型为：

```text
SRI_cg_smooth = beta1*GDI_x_Exposure_z + city FE + job_family FE + error
GenAIShare_cg_smooth = beta1*GDI_x_Exposure_z + city FE + job_family FE + error
SkillEntropy_cg = beta1*GDI_x_Exposure_z + city FE + job_family FE + error
```

逐步规格：

| 后缀 | 固定效应设定 |
|---|---|
| `1` | 无固定效应 |
| `2` | city FE |
| `3` | job_family FE |
| `4` | city FE + job_family FE |

正文主看 A4/B4/C4，其中 A4 是最核心主结果。主样本为 15 类岗位大类且 `job_count >= 10`。正文主表使用 HC3 稳健标准误；city cluster 与 job_family cluster 标准误作为诊断输出。

城市层模型可作为补充，但当前仓库尚未发现完全按下式输出的最终表：

```text
Y_c = alpha1*Exposure_c + alpha2*GDI_c + alpha3*(Exposure_c * GDI_c) + Controls_c + error
```

其中 `Y_c` 可为 `SRI_c`、`H_c`、城市 GenAI 技能占比等城市层结果变量。

## 11. 城市分类规则

城市分类主要基于三个指标：

| 指标 | 含义 | 当前状态 |
|---|---|---|
| `Exposure_c` | 城市结构加权岗位族暴露度 | 建议生成，当前未见标准输出 |
| `GDI_c` | 当前口径为城市显性 GenAI / LLM 岗位占比 | 已在机制模型中生成 |
| `SRI_c` | 城市整体技能结构重塑程度 | 建议由 `SRI_cg` 加权生成，当前未见标准输出 |

分类方法一：三分位数分类。

```text
GDI_group: high / middle / low
Exposure_group: high / middle / low
SRI_group: high / middle / low
```

其中三组分别由 `GDI_c`、`Exposure_c`、`SRI_c` 的三分位数划分。

分类方法二：二维象限分类。以 `GDI_c` 和 `Exposure_c` 的中位数为分界：

| 类型 | 定义 | 含义 |
|---|---|---|
| 高 GDI × 高 Exposure | `GDI_c >= median(GDI_c)` 且 `Exposure_c >= median(Exposure_c)` | GenAI 需求显性化强，AI 暴露岗位集中 |
| 高 GDI × 低 Exposure | `GDI_c >= median(GDI_c)` 且 `Exposure_c < median(Exposure_c)` | GenAI 需求显性化强，但岗位结构暴露较低 |
| 低 GDI × 高 Exposure | `GDI_c < median(GDI_c)` 且 `Exposure_c >= median(Exposure_c)` | 暴露岗位较集中，但显性 GenAI 需求较弱 |
| 低 GDI × 低 Exposure | `GDI_c < median(GDI_c)` 且 `Exposure_c < median(Exposure_c)` | 暴露和显性需求均较弱 |

输出字段建议：

```text
GDI_group
Exposure_group
SRI_group
city_type
```

当前仓库已有 `city_llm_classification_final.csv`，但其 `city_type` 是基于城市 LLM 暴露、增强潜力、替代风险、技能复杂度和样本量的解释型标签，不等同于本节的 `GDI × Exposure` 四象限分类。正式论文若使用四象限分类，应另行生成 `city_classification.csv`。

## 13. 质量检查与可复现要求

每次全量运行后至少执行以下检查：

| 检查项 | 规则 |
|---|---|
| `job_id` 去重 | 岗位层评分表中同一 `job_id` 不应重复；若重复需记录来源 |
| `city` 缺失率 | 缺失城市不得进入城市聚合；缺失率需报告 |
| `job_family` 缺失率 | 正文主表不得静默丢弃未映射岗位，应记录未映射数量 |
| `job_tags_raw` / `skill_tokens_v2_1` 缺失率 | 分基础标签覆盖率和 v2.1 控制 token 覆盖率报告 |
| `skill_coverage_ratio` | 检查城市和 `city × job_family` 两个层级覆盖率 |
| `n_cg` 分布 | 输出均值、中位数、分位数、`<5`、`<10`、`<20` 单元占比 |
| `H_cg` 异常值 | 不应出现负值；无技能单元应为缺失 |
| `Exposure_g` 缺失 | 所有正文岗位族应能匹配 `Exposure_g` |
| `GDI_c` 缺失 | 所有模型城市应能匹配 `GDI_c` |
| `SRI_cg` 计算 | 检查 `SRI_cg_smooth`、`SRI_cg_raw`、`SRI_cg_smooth_winsor` 是否生成 |
| 城市数量一致性 | `city_classification` 的城市数量应与目标城市样本一致，并说明是否为核心 195 城 |
| 标准化变量 | 所有用于模型的核心变量应有标准化版本或明确不标准化原因 |
| 缺失原因 | 所有缺失值必须有原因，不得静默丢弃 |

主结果表保留完整样本并标记质量；模型估计可以使用 `job_count >= 10` 主样本；稳健性可以使用 `job_count >= 5` 加权、`job_count >= 20` 严格样本、18 类岗位族、未平滑 SRI、缩尾 SRI 等口径。所有样本剔除必须有规则和记录。

## 14. 待确认问题

| 问题 | 影响 | 建议处理 |
|---|---|---|
| `GDI_c` 的论文命名与当前公式含义不完全一致 | 当前 `GDI_c` 是显性 GenAI / LLM 岗位占比，不是外部宏观城市数字基础 | 人工确认正文是否改称“城市 GenAI 需求强度”，或另补外部数字基础指数并改名 |
| 未发现正式 `Exposure_c = sum_g share_cg * Exposure_g` 输出表 | 无法直接按结构加权暴露做城市分类 | 从 15 类 `cg_panel_with_sri_smooth.csv` 派生 `share_cg` 后生成 |
| 未发现正式 `SRI_c` 城市聚合表 | 城市层“技能重塑程度”尚不能直接引用 | 按有效 `SRI_cg` 和重新归一化权重生成 |
| `city_llm_classification_final.csv` 的 `city_type` 不是 `GDI × Exposure` 四象限 | 城市分类口径可能混用 | 新生成 `city_classification.csv`，保留旧解释型分类作为补充 |
| 当前机制表缺少薪资、学历、经验、发布时间字段 | `panel_cg_model.csv` 控制变量不完整 | 从 `panel_cg_base_jobfamily_v1.csv` 或 15 类聚合表合并补齐 |
| `quality_flag` 命名在不同脚本中含义不一致 | 质量标记难以统一解释 | 建议保留原字段，并新增 `sample_size_quality` 或按本文档重命名 |
| 15 类主口径文件名中包含 `12to15` | 可能误导组员以为是 12 类 | 文档和论文中统一写为 `job_family_mapping_v2_15class` |
| 当前主要样本期为 2024-10-04 至 2026-04-20 | 与早期方案中 2021-2026 或季度面板表述不一致 | 正文按当前可用样本期写；若补历史数据再扩展 |
